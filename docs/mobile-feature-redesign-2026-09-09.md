# 移动端/小程序端功能梳理与设计建议

> 基于 uTools 桌面端全量功能清单，从移动端（微信小程序/抖音小程序/App/H5）视角重新梳理：功能取舍、信息架构与排版、可优化点、新功能建议。
> 与既有 `docs/mobile-mp-adaptation-plan-2026-09-06.md` 并存——该文管"适配进度"，本文管"功能维度该做什么、不该做什么"。

## 一、功能取舍总表

### 1. 建议不做（桌面强依赖，移动端无意义）

| 功能 | 原因 |
|---|---|
| 快捷键记忆/训练 | 手机无物理键盘，桌面路由本身也只对桌面注册 |
| 专注模式悬浮窗（置顶/贴边/透明度/鼠标穿透） | 小程序无多窗口能力；移动端已用全屏版 focus 页合理降级 |
| 输入法悬浮键盘 | uTools `createBrowserWindow` 子窗口专属 |
| 全局快捷键、加入单词后退出插件 | uTools 插件机制专属 |
| 主窗口透明度 | Electron 专属 |
| 登录/申请/审批/异常（Login/Apply/Check/Exception） | 桌面端已废弃的遗留页面，移动端无需继承 |
| OCR 截图框选翻译 | 移动端无屏幕截图 API；拍照 OCR 取词已覆盖核心场景 |

### 2. 核心重点功能（移动端的主战场）

移动端的使用场景是**碎片时间复习**，与桌面端"录入+深度学习"互补。优先级：

1. **单词 SRS 复习**（翻卡手势版 review 页）——最高频操作，应是体验最重的页面
2. **今日待办聚合**（首页统计卡 + 待复习数）——打开 App 第一眼看到"今天该学什么"
3. **听写/拼写练习**——触摸输入体验已适配，是移动端比桌面端更顺手的场景
4. **错题本**——移动碎片化复习的天然入口
5. **打卡**——移动端留存抓手，连续打卡激励
6. **文本背诵（诗词/文章）**——排队通勤场景友好，已有诗词地图亮点
7. **拍照 OCR 取词 → 翻译 → 一键入词库**——移动端独有优势场景（摄像头），比桌面截图链路更短

### 3. 保留但可降级/简化

| 功能 | 建议 |
|---|---|
| 记忆宫殿 | 维持 P3 缓做判断。只做「查看 + 巡视复习」，编辑（大图/拖拽/排序）留桌面端 |
| 数字记忆 | 保留训练 + 条目复习 + 图片桩（已完成）；映射表编辑可简化 |
| 音标系列 4 页 | 已完成，保持 |
| 知识库 | 维持精简版（翻卡+四选一）；自建条目编辑不做 |
| 多引擎翻译 | 10 引擎够用；Gemini/OpenAI/Claude 等国内访问受限引擎不补 |
| 多端同步 | 服务器同步（同步码/扫码）已可用；文件同步导入导出可不做（小程序文件体验差） |
| 字母映射记忆（LetterMemory） | 桌面端也是小众功能，移动端可不做或并入数字记忆编码 |

## 二、信息架构与排版建议

### 现状问题

首页快速入口已有 12 个宫格入口（复习/拼写/翻译/添加/打卡/词库/数字记忆/音标/文本记忆/记忆测评/知识库/专注模式），开始拥挤；tabBar 4 项（首页/单词/复习/我的）合理。

### 建议结构

**tabBar 保持 4 项不变**，首页入口按「频次 × 场景」分层：

- **首屏：今日任务区**（非宫格）
  - 大卡片：今日待复习 N 词 → 直接进复习
  - 次级条：待复习文本 M 篇 / 错题 K 条 / 连续打卡 D 天
  - 原则：首页首屏只放"今天该做什么"，不放功能目录
- **次屏：功能宫格收敛为 6~8 个**，按使用频次排序：
  复习、拼写、文本记忆、翻译（含拍照取词）、打卡、数字记忆；其余（音标/测评/知识库/词库管理/专注模式）收进「全部功能」或移到「我的」页
- **「我的」页**：设置（翻译引擎/密钥）、同步、词库管理、关于——低频管理类操作归此

### 排版要点

- 复习页是全App核心，保持全屏沉浸式（现有手势翻卡已好），其他页面不要抢它的层级
- 文本记忆/诗词地图这类内容型页面，列表优先大图卡片，移动端阅读优先
- 专注模式全屏版入口可放在复习完成后的引导（"再来一组专注模式"），而非首页宫格

## 三、可优化的实现点

1. **首页统计卡 → 可点击直达**：待复习数点击直接开始复习，减少一步跳转
2. **复习完成页引导链**：复习结束 → 引导听写/错题本/打卡，形成闭环
3. **拍照取词链路缩短**：翻译页拍照 OCR 结果页直接提供"加入词库"按钮（当前需手动去 add-word）
4. **TTS 发音**：当前仅有道 dictvoice 音频 URL；可增加失败重试与本地缓存，弱网体验更稳
5. **打卡纳入同步 payload**（当前未同步，换设备丢记录）
6. **同步二维码**：拉取已有扫码；推送端可生成二维码方便桌面端扫（反向链路补齐）
7. **复习手势反馈**：左划忘记/右划认识可加触感震动（uni.vibrateShort）强化确认感

## 四-补、数学公式 / 化学元素表的专项安排

**现状核实**：这类内容不需要新建模块——它们已经是「知识库」内置包，且移动端 35 个包已全部转换完成（`mobile/src/subPackages/pages-knowledge/knowledgebanks/*.ts`）：

- 数学 5 包：常用数学公式 33 条、数学公式 2、微积分、线性代数、概率论
- 物理 3 包：初中物理公式、物理定律、物理实验
- 化学 2 包：初中化学式与方程式、元素周期表（前 54 号，含"氢氦锂铍硼"口诀 mnemonics）
- 另有关联包：乘法口诀 9×9 / 19×19、平方立方幂、100 以内质数

现有练习方式：翻卡 + 四选一 + 口诀展示，公式以 Unicode 纯文本渲染（S=πr²、½ah）。对中学级公式够用，但微积分/线代里的分式、积分、矩阵纯文本表达力不足；元素表用翻卡学符号↔名称可以，但丢了"周期表"这张最重要的结构图。

**建议安排（按优先级）**：

0. **先修四选一干扰项质量**（小改动、立即见效）：当前 `generateChoices`（`mobile/src/subPackages/pages-knowledge/useKnowledgeMemory.ts:267`）是纯随机从本包抓 3 个答案，元素表会出"氢/锰/氙/溴"这种一眼假的选项。改为相似度优先：
   - 元素包：优先取**相邻原子序数 / 同周期 / 同族**元素（extras 有序数，可加行列坐标后直接算）
   - 公式包：优先取**同章节/同类型**公式（extras 补 category 字段，或按 question 关键词聚类，如"面积""体积"各自成组）
   - 通用兜底：按答案的字符集与长度做相似度排序（编辑距离），保证干扰项"长得像"
   - 同一套逻辑也应回灌桌面端 `generateChoices`，双端共享策略
1. **元素周期表视图**（小改动、收益直观，但**竖屏 18 列网格是伪可用设计，需修正**）：手机竖屏仅 ~375px 宽，18 列真周期表每格不足 20px，字放不下也点不中。修正为两种形态：
   - 默认：**按周期分组的列表**（第一周期一行、第二周期一行……同族用缩进/颜色暗示），点元素弹详情——竖屏下唯一"简洁无脑"的形态
   - 可选：横屏或横向可滚动/双指缩放的完整 18 列网格，作为"看结构"的辅助视图
   数据在 extras 补「行/列」坐标（或按序数推导）。
2. **打字填空改为「点选拼答案」**（中改动，需加长度闸）：移动端打字输入公式/化学式体验差（切符号键盘、上下标打不出来），不做键盘填空。改为 Duolingo 式**碎片点选**：把答案拆成 token（字母/符号/数字/汉字，如 `S` `=` `π` `r` `²`），打乱成格子，用户按序点选拼出完整答案，判分即比较 token 序列，全程零键盘。**限制：答案超过 ~8 个 token（如泰勒公式）时点选变得繁琐，自动回退为翻卡自评**，不强行点选。单词拼写练习同理可加字母碎片模式，长单词同样回退。
3. **知识包分类标签**（小改动）：knowledge-list 页当前只有"我的/内置"双 tab，35 个包可加分类筛选（数学/物理/化学/语文/记忆桩/地理…），数据已有天然归类。
4. **复杂公式渲染**（可缓，修正渲染目标）：微积分/线代包的复杂公式若 Unicode 不够用，构建期把公式**预渲染成 PNG 图片**打进知识包——微信小程序 `image` 组件**不支持 SVG**，不要走 SVG 路线。不建议在小程序端引入 LaTeX 解析库。
5. **函数图像 FunctionPlot**（可缓）：桌面端知识包里的函数图像可视化，移动端可用 canvas 2d 简化实现，但优先级最低——记忆场景里"看图"价值低于"动手拼"。

化学方程式与物理公式维持现有 Unicode 文本展示即可；练习侧靠「智能四选一 + 点选拼答案 + 翻卡」三种模式覆盖，不需要键盘输入。

## 四、可新增的功能（移动端独有优势，已按"小程序实际能力"过滤）

1. **复习提醒（降级设计，勿承诺推送）**：微信工具类小程序只有**一次性订阅消息**——每推一条就要用户手动授权一次，无法做到"每天自动提醒"，长期订阅消息仅对政务医疗等类目开放。因此提醒主战场不是推送，而是：**打开即见的今日待办首屏**（已有）+ 用户主动订阅时的一次性提醒（作为加分项）。不要在规划里写"到期推送"这种兑现不了的能力。
2. **连播听词模式（去掉"锁屏"承诺）**：亮屏状态下连续播放今日待复习单词+释义，配合防熄屏（已有 focus 页的防熄屏能力可复用）。**小程序锁屏/退后台后音频会被系统回收**（InnerAudioContext 不可靠，背景音乐通道对内容类目有审核限制），"锁屏听词"做不到，只做亮屏连播。
3. **分享卡片**：打卡成就/背诵成绩生成分享图（canvas 已有基础），小程序常规传播能力，可行。
4. ~~语音输入查词~~ **不做**：小程序无原生语音识别，需接微信同声传译插件或自建 ASR，链路长、场景低频，不符合简洁无脑。
5. ~~App 桌面小组件~~ **不做**：UniApp 需原生插件/离线打包，成本与收益不成比；安卓微信的"添加到桌面"是微信自带能力，无需开发。
6. ~~好友排行榜~~ **不做**：无账号体系，且偏离工具定位。

## 四-再补、计划中排查出的「伪可用」设计点汇总

以下是从本计划初稿中揪出的"纸面正常、实际不可用/反直觉"项，已在上文就地修正：

| 原设计 | 问题 | 修正 |
|---|---|---|
| 元素周期表 18 列网格 | 竖屏每格 <20px，点不中 | 默认周期分组列表，网格仅横屏/可缩放 |
| 订阅消息每日复习提醒 | 一次性授权，推一条授权一次 | 主靠首屏今日待办，订阅仅辅助 |
| 锁屏/息屏听词 | 小程序后台音频被系统回收 | 只做亮屏连播 + 防熄屏 |
| 公式预渲染 SVG | 小程序 image 不支持 SVG | 构建期渲染 PNG |
| 语音查词 / App 小组件 / 好友排行 | 链路长/成本高/无账号体系 | 移出规划 |
| 点选拼答案无长度限制 | 长公式点选比打字更累 | >8 token 回退翻卡自评 |

通用判定准则（后续新增功能逐条过）：
- **一步能到的不要两步**：入口点击后必须直接开始学，中间不插选择页
- **能不打字就不打字**：一切输入优先点选/手势/拍照
- **不依赖系统不给的能力**：推送、后台、多窗口、文件系统都按小程序真实边界设计
- **不照搬桌面信息密度**：桌面一屏 30 行的表格，移动端必须换形态（列表/卡片/网格点选）

## 五、落地建议（如进入实施）

按投入产出排序：

- **S1（小改动，体验收益大）**：四选一干扰项质量修复（相似度优先，双端同步改）、首页"今日任务区"改造、宫格收敛、复习闭环引导、打卡入同步 payload、拍照取词直达入库、元素周期表分组列表视图、知识包分类筛选
- **S2（中改动）**：点选拼答案模式（知识练习 + 单词拼写通用，带长度闸）、亮屏连播听词（复用防熄屏）、一次性订阅消息提醒（仅辅助）、TTS 缓存重试、分享卡片
- **S3（大改动，可缓）**：记忆宫殿查看版、复杂公式预渲染 PNG、函数图像 canvas 版、横屏完整周期表网格

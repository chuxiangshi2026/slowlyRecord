### 3.3 数字记忆（✅ 2026-11-22 已按方案重设计）

**现状流程**：桩位配置（00–99 共 100 格网格，逐格编辑）→ 添加数字条目（标题+数字串）→ 练习（看标题硬回忆数字 / 看数字硬回忆桩）。

**为什么难用（确诊）：**
1. **零教学**：用户不知道"桩"是什么、为什么记数字要先记 100 张图。首屏就是 100 格配置网格，直接劝退
2. **默认桩只有 0–20**（default-pegs.ts），"一键填充"后 21–99 仍全空，配置工作量没有真正省掉
3. **缺"编码"环节**：加了条目「妈妈的手机 13912345678」后，任何地方都看不到它对应的桩链和故事——而这恰是桩法记忆的核心价值。练习就是干回忆，没有桥梁
4. **练习无渐进**：上来就是纯回忆，没有选择题过渡，挫败感强

**重设计方案（核心：把"编码"做出来，让桩链可见）**

1. **补全 00–99 默认桩表**，内置为开箱即用，「桩位配置」降级为高级设置（藏到二级页）。用户零配置即可开始
2. **首次进入 3 步引导**，用真实例子走完全流程：
   - 第 1 步：讲解"把数字变成图像"——`13 = 雨伞（谐音）`
   - 第 2 步：自动演示编码「妈妈的手机 139 1234 5678」→ 分对 `1-39-12-34-56-78` → 桩链：蜡烛→(39 对应桩)→椅儿→… → 拼成一句故事
   - 第 3 步：请用户输入一个自己的号码，现场生成桩链故事，完成"啊哈"时刻
3. **条目详情加「编码视图」**：数字串自动分对，每对显示桩图/描述，下方一句可编辑的记忆故事；这才是条目页的主角，数字本身退为答案
4. **练习改四档渐进**：
   - L1 认桩（看数字，4 选 1 选桩图）
   - L2 背桩（看数字回忆桩，即现有 pegs 模式）
   - L3 编码复述（看数字串 → 回忆桩链故事 → 揭示对照）
   - L4 实战（看条目标题默写数字串，即现有 entries 模式）
5. **场景模板**：添加条目时给「手机号 / 生日 / 银行卡 / 身份证 / 车牌」模板，自动按位数分对（手机号 1-3-3-4 是反桩法的，应按 2-2-2-2-2-1 切）
6. 与记忆宫殿联动：桩就是桩，宫殿房间可以挂数字桩（长期，后置）

**验收例子**：新用户 3 分钟内，不配置任何东西，能完成「输入家人生日 → 看到桩链故事 → L1 练习答对 5 题」。

**落地情况（2026-11-22）：**
1. ✅ 默认桩表补全 00–99 全覆盖（`default-pegs.ts`，单测守护全覆盖），一键填充即可开箱
2. ✅ 首次进入 3 步引导（什么是桩 → 手机号编码演示 → 一键填充），只弹一次（storage 标记）
3. ✅ 编码视图：条目卡显示桩链故事（🔗 蜡烛 → 三角 → …）；entry-edit 输入时实时显示桩链（顺带修正了旧「桩提示」奇数位切分错误）
4. ✅ 练习四档：认桩（4 选 1）/ 背桩 / 编码复述（看数字串背桩链）/ 实战（看标题背数字），实战答案下也附桩链
5. 场景模板（手机号/生日/银行卡）与记忆宫殿联动未做，视使用反馈再补

### 3.4 口语句库与预合成连读音频（✅ 2026-11-22）

**背景**：用户反馈「卡片练习部分句子无法发音」——长句走 dictvoice 失败、回退 Google TTS 在国内/微信内被墙无声；同时口语句子太少、词库分类缺「英语」汇总。

**口语句库扩充至 6 库 3000 句**（`public/wordbanks/spoken-*.json`，双端共用，全部带预合成音频）：

| 词库 | 内容 | 条数 |
|---|---|---|
| spoken-reductions-1 | 连读弱读 I（gonna/wanna/didja 等） | 500 |
| spoken-reductions-2 | 连读弱读 II（must've/y'know/finna 等 29 组） | 500 |
| spoken-elision-1 | 略读省音（walkin'/'cause/'em/las' 等 7 类） | 500 |
| spoken-liaison-1 | 连读规则（辅元连读/滑音/闪音/h击穿/失去爆破 7 类） | 500 |
| spoken-reactions-1 | 口语反应 I（高频短反应） | 500 |
| spoken-reactions-2 | 口语反应 II（赞同/惊讶/推脱/吐槽等 13 场景） | 500 |

- 质量闸门：每库 500 条、freq 1–500 连续、字段仅 word/explains/freq，**6 库跨库零重复**（含修复 reactions-1 与 reductions-1 的 7 条历史撞词）
- 桌面端注册于 `wordbank-service.ts`（EXTENDED_WORDBANKS，speechAudio 标记）；移动端注册于 `remote-wordbank.ts`（PUBLIC_HOSTED_BANKS，归「口语句型」分类，jsDelivr 托管下载）

**预合成连读音频接入移动端（发音失败修复主线）**：
1. 音频由 `scripts/generate_speech_audio.py` 离线合成（edge-tts en-US-AvaNeural、rate +5%），文件名 `md5(voice|rate|归一化文本)`，托管 jsDelivr `public/speech-audio/<bankId>/`
2. `mobile/src/utils/md5.ts`：内置精简 MD5（小程序不能用 crypto-js），RFC 1321 标准向量 + 中文 UTF-8 + 生成侧实际输入交叉验证
3. `mobile/src/utils/speech-audio.ts`：与桌面端同哈希口径，返回 jsDelivr 音频 URL
4. `word-audio.ts` 新增 `speechBankId`：预合成录音放音源链最前，失败回退有道/Google TTS
5. 导入口语句库时词条写入 `speechBankId`（wordbank.vue importToBank）；复习页 / 专注模式 / 听写发音均已接线
6. **真实连读/弱读/略读发音**：预合成音频按完整口语形式合成（如 wanna 读 /ˈwɑːnə/），覆盖连读、弱读、略读、闪音——这是机器 TTS 逐词朗读做不到的

**词库分类「英语」汇总 tab**（2026-11-22）：分类栏顺序 = 全部 / 英语 / 考试 / 分级 / 口语句型 / … / 日语 / 俄语…，与非英语语种 tab 对齐；`buildCategoryTabs` 在含英语词库时自动补「英语」tab，筛选特判 `(language||'en')==='en'`。

### 3.8 长音频播放修复 + B站翻译引擎（✅ 2026-11-22）

**「中文朗读只读一段就回到开头重读」根因**：TTS 适配器的看门狗是 15 秒「总时长」超时——单词音频够用，诗词/长文朗读必超时被强制 stop，重试又从 0 秒开始，表现为读到一半回到开头。修复：
- 看门狗改为「无进展」计时：`onTimeUpdate`/`onCanplay` 每次进度推进都重置计时器，只有真正卡死（15 秒无任何进展）才判失败，长音频可播任意时长
- 中断重试带断点续播：失败时记录已播放进度，重试用 `InnerAudioContext.startTime` 从上次位置续播（不会从头再来）

**B站翻译引擎（桌面端已有、移动端补齐）**：B站 Index-Translate（`index-translate.bilibili.com`，免密钥公网 AI 接口）加入移动端：`TranslationPlatform` 增加 `bilibili`（stores 类型 + config 默认键表），翻译设置页可直接选择（无需填密钥，`resolveEffectiveTranslationPlatform` 免密钥直通），pages-tools 翻译页与主包 quick-translate（「译英文」）均接入，含思维链标签剥离与限流（429）提示。

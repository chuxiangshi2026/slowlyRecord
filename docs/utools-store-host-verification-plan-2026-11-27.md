### C. 静态与 CI 收口

1. 对**准备提交的最终插件目录**运行 `utools-plugin-selfcheck` 静态检查。它只检查发行内容，不执行包内代码；保存“必须整改 / 建议整改”的结论。测试副本中的改动另记，不替代正式发行目录自查。
2. 对照 [商店收口计划](./utools-store-review-hardening-plan-2026-11-26.md)检查权限说明、preload 能力、隐私页、版本、构建剥离和旧统计端点。已有自检能复用时记录构建时间与哈希；源文件变化后必须重新构建和扫描。
3. 只读查询目标提交的 CI `quality`、`builds`。若 `gh` 继续无法识别远端，可核对仓库已配置的 GitHub 仓库地址和可访问的 CI 页面；不得为触发 CI 擅自推送。没有对应最终提交的绿色结果，填写“未核实”，不得写“CI 通过”。
4. 若验收中确认缺陷，记录代码位置、复现、影响、严重度及关闭条件。修复授权另行取得；修复后按仓库质量流程执行 `npm run test:run`、类型检查、`npx vitest run src/app-enter.test.ts`、`npm run build:store`、商店产物 E2E，并重新验收受影响的真实入口。旧产物证据全部标为过期。

### 提审判定

- **建议提审**：目标产物身份已固定；核心宿主入口、截图失败恢复、专注窗和统计同意链路验收通过；发行目录自检及最终提交的 CI 均通过；无未接受的 Blocker/Major；剩余小问题由负责人明确接受并记录。
- **暂不建议提审**：仍只能操作旧版、宿主核心场景未执行、统计开关时序无证据、CI 未核实，或存在未关闭的 Blocker/Major。
- **部分完成、等待人工配合**：代理可完成静态和可控场景，但搜索框失焦、截图选区或跨应用划词无法可靠自动化时，明确列出要用户现场操作的最小动作；不要把工具限制说成插件功能缺陷。

域名 HTTPS 已可用，证书旧记录于 **2027-02-24** 到期；续证、HTTP 跳转及 CORS 优化单列维护任务，不在本轮宿主验收中改变云端设置。favicon 404 是低风险收尾项，不应取代上述 P0 宿主证据。

# 增长路线图（2026-10-28 制定，2026-10-29 复核，2026-10-30 更新实施状态）

> 工作量均为开发估算，不含域名备案、商店审核和第三方平台审批时间。

## 判断

平台数量不是瓶颈。仓库已有 6 个构建目标（uTools / Electron / Web / 微信 / 抖音 / App），
当前应先验证**公开入口、首启激活、内容分发**，再决定是否投入新平台。

内容资产可复用：`public/wordbanks/` 有 57 个词库文件、74,999 条词/短语/句子，
`public/datafile/poetry/` 有 455 首诗词。它们目前主要服务于客户端，尚未形成搜索和分享入口。

修订原则：
- **导入导出是防线**，降低迁移和流失，不直接带来新用户。
- **静态页同时承担 SEO 和内置内容分享**，不再重复开发一套 URL 压缩快照协议。
- **翻译代理不再是 Web 上线前置**。实测已有可跨域的免费接口，先做浏览器直连。
- **扩展按真实数据决定是否启动**，不提前锁死 6–8 天投入。

## P0a：Web 公网 smoke 版（2–3 天）

### 目标

公开链接可访问，新用户能完成「选词库 → 背一组 → 刷新后进度仍在」，无密钥也能翻译。
先验证主流程，不要求第一版就覆盖所有桌面端能力。

### 步骤

1. **部署**
   - 根路径部署时把 `vite.config.web.ts` 的 `base: './'` 改为 `'/'`；hash 路由保证刷新不 404。
   - 静态托管可先用 CloudBase；现有同步服务是 SCF 函数 URL，不能据此假定静态托管与函数
     天然同域或同账号。
   - `dist-web/` 约 29MB 是总产物，不代表首屏流量。按浏览器网络面板和 Lighthouse 判断性能，
     不按目录大小盲目优化。
   - 当前 Web 产物也会包含 `plugin.json`、`preload/` 等 public 文件；不影响运行，但 PWA
     预缓存必须白名单化，不能全量预缓存。

2. **真实浏览器验收，而不是只验证能构建**
   - 桌面 Chrome / Edge、手机 Safari / Chrome、微信内置浏览器至少各跑一遍核心流程。
   - 检查 IndexedDB / localStorage 不可用或空间不足时是否明确报错，不能静默假装保存成功。
   - 首启已有 `OnboardingOverlay.vue`，重点改平台文案：Web 端不能继续提示 uTools 的
     「划词添加」「截图添加」。
   - 平台能力按现有 feature detection 逐项处理。不要笼统删除本地 OCR：Web 适配器已经支持
     选图，Tesseract 也是懒加载；只隐藏实际不可用的系统截图、悬浮窗等入口。

3. **无密钥翻译：先修直连，不做代理**
   - 2026-10-29 实测：
     - Google `translate_a/single` 返回 `Access-Control-Allow-Origin: *`，请求成功；
     - B 站 Index-Translate 返回 `Access-Control-Allow-Origin: *`，无密钥 POST 翻译成功；
     - Spark 预检返回 403；GLM 预检未返回允许跨域的响应头。
   - 因此 `translation-api.ts` 对 Google / 微软的 Web 禁用判断需要重新验证，Web 免费引擎
     降级链应按浏览器实测结果排序，优先直连可用引擎。
   - 免费/非官方接口没有稳定性承诺，保留失败降级和明确错误提示。CURL 结果只是上线依据，
     最终仍须在真实浏览器验证。

4. **隐私、统计与反馈在上线时一起完成**
   - 隐私页不能只写“服务器只存加密同步数据”。还需说明：匿名使用统计与异常上报、翻译文本
     会发送给所选引擎、OCR 图片会发送给所选服务、API Key 的本地存储方式，以及统计退出方式。
   - 现有 umami 已覆盖 launch / pageview / error / word.add 等事件；补首启激活事件即可，
     不另建统计系统。
   - 增加反馈入口（GitHub issue 或邮件）。

### 验收

```bash
npm run build:web && npm run type-check && npm run test:run
```

- 新用户不配置 Key，能导入词库、复习、翻译；刷新后数据仍在。
- 首启文案与实际 Web 能力一致，无点击后才报错的桌面专属入口。
- 断网、存储失败、翻译失败均有可理解的提示。
- 隐私页内容与实际数据流一致。

## P0b：PWA 与离线增强（约 1 天）

- 仅在 smoke 版核心流程通过后加入 `vite-plugin-pwa`。
- 预缓存应用壳和必要静态资源；`wordbanks/`、`datafile/` 等同源数据按需缓存，不预缓存全部
  29MB，也不缓存无用的 uTools 文件。
- 离线承诺限定为：**已成功加载过的应用壳、词库和复习数据可继续使用**；不能承诺首次断网
  打开或从未加载过的远程词库也可用。
- 更新尽量在下次启动生效，复习过程中不强制刷新；升级不能清空 IndexedDB / localStorage。
- manifest 图标由 256×256 的 `public/logo.png` 生成所需尺寸。

验收：首次在线访问后断网刷新可用；已导入词库可复习；版本更新后数据不丢；未访问的远程
资源离线时给出明确提示。

## P1：静态内容页小批量试点（1–2 天）

### 试点结果（2026-10-30）

已由 `scripts/gen-seo-pages.cjs` 生成并接入 `npm run build:web`：

- 12 个考试词库页（中考/高考/四六级/商务英语/专四/专八/SAT/考研/雅思/托福/GRE）
- 22 个公版诗词页（含原文、拼音、标签；不含第三方英译）
- 1 个内容索引页 `/library.html`
- `sitemap.xml`、`robots.txt`、canonical、JSON-LD、页面间内链
- 词库 CTA 深链打开导入预览并预选词库，必须用户确认后才写入

### 范围

先做 10–20 个核心词库页和代表性诗词页，验证收录与点击，再全量生成。全量上限约：
57 个词库页 + 455 个诗词页 + 作者/朝代聚合页。**不生成 74,999 个独立词条页**，避免薄内容。

### 实现约束

- 新增构建脚本读取 `public/wordbanks/*.json` 和 `public/datafile/poetry/*.json`，生成真实 HTML、
  `sitemap.xml`、`robots.txt`、canonical 和必要的 JSON-LD。
- 词库名称/简介以 `WORDBANK_LIST` 为元数据源，条数以实际 JSON 为准。当前元数据有 58 项，
  public 只有 57 个文件，`roots` 没有对应 JSON；生成器必须显式报告并跳过，不能产出空页。
- 页面包含完整服务端生成的正文，禁用 JS 也能阅读；正文、属性、URL 全部转义。
- 建立首页/词库页/诗词页之间的普通 `<a href>` 内链。sitemap 不是收录保证。
- 静态页本身就是内置内容的分享链接，不再做 `#/s?d=<压缩数据>`。长诗如《琵琶行》含拼音和
  英译后远超 1KB，也不适合全部塞进 URL。
- CTA 深链需要新增处理，例如 `/#/word?builtin=cet4&from=seo`：打开导入预览，由用户确认，
  不能访问链接就自动写入数千词条。扩展用的 `add` 深链也同样需要确认。
- 来源参数放在 hash 之前；当前 `stats.ts` 只读取 hash，需在实现时保留并上报首次来源，
  否则无法衡量 SEO 转化。

### 内容授权前置

- 先确认词库释义及第三方内容的再发布权。 v1 优先使用权属清晰的考试词汇和公版古诗。
- `movie-lines`、名言类内容及 64 首第三方英译在授权核对前不做公开静态页。
- `NOTICE` 已明确：上游 MIT 许可证只覆盖英译 JSON 的汇编，不授予底层英译版权；
  页面保留来源和移除机制不等于获得授权。

### 域名与备案

备案不是所有搜索引擎收录的硬性前提，但国内托管自定义域名通常需要备案。默认函数/托管域名
不适合作为长期品牌和 canonical；没有自有域名也可试点，但不要承诺 1–3 个月必然起量。

### 验收

- 原始 HTML 含完整正文、title、description、canonical；错误路径返回真实 404。
- sitemap 数量与生成页面一致，无空页和重复 ID。
- CTA 能到达对应词库的导入预览，来源事件可在 umami 观察到。
- 观察指标：内容页访问 → CTA 点击 → 导入成功 → 首次复习完成；不以上线页面数作为增长成果。

## P4：浏览器扩展 v1（有条件启动，6–8 天）

### 启动条件

Web 上线并运行 2–4 周后，结合激活率、留存和反馈决定。若首启转化差，先修 Web/首启，
不用扩展掩盖产品问题；若没有划词需求证据，不启动本阶段。

### v1 范围

用户选中文本后，通过**右键菜单或快捷键**触发翻译浮层；点击图标打开 Web 应用。
不做新标签页接管，不做第二份 IndexedDB，不做自动选词弹窗。

- `activeTab` 的临时权限与用户主动触发相匹配；如要自动监听所有页面选词，就需要更广泛的
  content script 权限，不能同时宣称“自动划词”和“只使用窄权限”。
- 权限：`activeTab`、`contextMenus`、`scripting`、`storage`；网络请求放 background，
  host permissions 只申请实际需要的 API 域名。
- 「加入词库」打开 Web 的确认页，不直接写数据。
- 所有脚本随包内置，不加载远程 JS；先 Edge，再视情况上 Chrome。
- 隐私政策按 P0a 的完整数据流编写，商店表单与产品行为一致。

## 暂缓事项

### 翻译代理

仅在真实浏览器证明免费直连失败率高、引擎不稳定，或确有服务端密钥需求时开发。
现有 SCF `/ping` 实测允许跨域，但静态托管与 SCF 不是天然同域；代理要么配置受控 CORS，
要么通过自定义域名路由，不能直接写成“同域代理”。

若实施：只代理服务端自有的内置免费引擎，不转发用户 BYOK 密钥；限制引擎、文本长度、
每 IP 与全局额度，配置成本告警，不记录翻译文本和密钥。Origin 白名单不是身份认证。
开发前先把现有云函数源码纳入 `cloudfunctions/`，目前仓库只有线上地址，没有函数源码。

### 自定义快照 URL、订阅消息服务端

- 内置内容分享已由静态页覆盖；自定义内容先沿用导出文件/分享图，等有需求再设计快照协议。
- 微信工具类一次性订阅每次授权只能推一条，且模板需管理员申请；继续用首页待办和桌面端
  现有提醒，不投入服务端推送。

## 里程碑与决策点

| 阶段 | 产出 | 继续/停止依据 |
|---|---|---|
| 第 1 阶段 | Web smoke 版 | 核心流程通过、无密钥翻译可用 |
| 第 2 阶段 | PWA + 静态页试点 | 首启转化可测、页面可抓取、CTA 可用 |
| 第 3 阶段 | 小程序分享、CSV 验证 | 真实分享和迁移流程可用 |
| 第 4 阶段 | 决定是否做扩展 | 2–4 周数据与反馈，而非预设排期 |

需要先确认的非代码事项：
1. 部署账号、长期域名及是否备案。
2. Web 首发支持的浏览器/设备范围。
3. 词库释义、电影台词、名言和第三方英译的公开再发布权。
4. 扩展是否在观察期后启动，以及翻译代理未来由谁承担额度成本。

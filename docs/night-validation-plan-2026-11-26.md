```bash
node scripts/e2e/blackbox.cjs --dist dist --out test-results/night-validation-2026-11-26/<run-id>/utools-renderer
node scripts/e2e/blackbox.cjs --dist dist-web --out test-results/night-validation-2026-11-26/<run-id>/web
node scripts/e2e/blackbox.cjs --dist dist-electron --out test-results/night-validation-2026-11-26/<run-id>/electron-renderer
```

`<run-id>` 是占位符，实际执行前替换为本轮唯一值，不能原样粘进 shell。现有脚本已支持 `--out`，无需修改业务代码。

最后单独构建商店版：

```bash
npm run build:store
```

- 商店构建会覆盖 `dist/`。必须先保存普通构建的 E2E 证据；商店产物若另跑 E2E，使用新的 `--out` 路径，清晰区分两份产物。
- 构建失败的目标不得用上次遗留产物继续测试并计为本轮通过。
- `lang-core.js` 普通脚本与动态/静态导入警告保留原始输出，先验证实际加载和测量性能，不为消除警告重构依赖或直接加 `type="module"`。
- Web / Electron 渲染产物上的浏览器 E2E 不等于 Electron 原生文件 API 或 uTools 宿主验收。
- Electron 原生文件选择、保存、取消以及 uTools 截图/划词，仅在工具和隔离数据已就绪时验证；缺少控制通道就列为未执行，不让低优先级平台拖住微信结果。
- 没有推送授权，不为确认 CI 而提交推送。CI Node 20 兼容性可在已有本地运行时下只读验证；否则记“未触发 CI”，不自动安装或替换运行时。

## 9. 不频繁中断的处理规则

| 情况 | 执行动作 | 是否结束整批工作 |
| --- | --- | --- |
| 临时网络失败、浏览器启动偶发失败 | 记录原始失败；有明确原因时纠正环境并重试一次 | 否 |
| 同一命令重复失败 | 保留每次退出码与错误，转替代验证和其他独立项目 | 否 |
| 手机未连接、扫码/登录/原生授权缺失 | 标记真机受阻，完成模拟器及自动检查 | 否 |
| IP 白名单拒绝、工具未注入、缺依赖且需安装 | 记录最小外部前置条件，不反复问用户 | 否 |
| sandbox / 工具要求审批 | 走规定审批机制，未获批不运行依赖动作；继续不依赖该权限的任务 | 仅受阻分支停止 |
| 发现真实业务缺陷 | 最小复现、定位、存证，按默认只读边界汇报 | 否 |
| 发现测试污染个人正式数据的可能 | 立即停止该写入路径，改隔离测试或只读验证 | 仅危险分支停止 |
| 用户明确要求停止 | 保存当前检查点并停止 | 是 |
| 所有剩余步骤均缺外部条件 | 写完整报告，集中列出条件并交接 | 是，结论为部分完成 |

其他规则：

1. 不以“环境不完美”提前结束；先完成全部可执行任务。
2. 不以“尽量不中断”为由伪造通过、无限重试、长期等待扫码、扩大授权或跳过必需审批。
3. 同一失败最多初次执行加一次有理由的重试；出现明确新证据才再次执行。业务断言失败不能靠重复运行碰绿。
4. 建议单条测试/构建命令超时 20 分钟、单端 E2E 15 分钟、单次自动化连接 90 秒、预览命令 10 分钟。超时先保存日志、判断是否仍有进展，不静默杀死还在正常推进的过程；终止只针对本轮创建并记录的进程。
5. 超时后的微信项目配置、设备状态和测试数据清理必须有结果；不能终止全部 Node 或微信进程。
6. 每个阶段写一次检查点；持续执行时约每分钟输出一次简短进度，工具输出不能替代用户进度说明。
7. 构建和 E2E 之间若受检源码被其他代理修改，当前产物标为旧基线，受影响项重建后再验；不重复运行无关平台。

## 一、P1（功能错误，本轮优先）

### R1 选择题近反义词出题错误、判断题缺失

- **现象**：词汇量测试/记忆测试的选择题中"近义词/反义词"题型语义理解错误（选项与题干不匹配）；判断题（对/错）题型缺失。
- **来源**：sl问题.md「选择题近反义词完全理解错了 / 判断题缺失」。
- **排查结论（2026-11-16 代码走查，共发现 5 处缺陷，均已修复）**：
  1. 关键词抽取把所有 4 字 n-gram 都当候选，4 字子串占位把 2 字库词挤掉，句中几乎选不出真词；
  2. 近/反义词题对词库外的词硬出：正确答案退化为「原词本身」/「不+原词」；
  3. `judgment` 判断题在类型定义与标签里已预留但生成逻辑未实现；
  4. `explanation` 解析生成后未写入题目对象，答题解析从未展示过；
  5. 生成函数不接收题型白名单，生成混合题后按勾选过滤，题量常不足。
- **修复**：语义题改为 4→2 字贪心匹配语义词库出题、无库词跳过/降级无厘头；实现判断题（陈述 50% 真/假，选「说法正确/错误」）；解析落库；白名单传入生成函数。新增 3 条回归测试。

### R2 知识库页面底部一行被遮盖

- **现象**：元素周期表非全屏时最下面一行被遮盖；知识库其他页面同样存在。移动端小程序亦同（原记录两条合并）。
- **来源**：sl问题.md「元素周期表，没有全屏的情况下还是看不全……知识库的其他页面也有同样的问题」。
- **排查结论与修复（2026-11-16）**：
  - 桌面知识**包**页上一轮已修（cffc591，页根 `flex-shrink: 0` + `padding-bottom`）；
  - 桌面知识库**列表**页同处 column flex 滚动容器下、此前无防护，本次补 `flex-shrink: 0`；
  - 移动端 `knowledge-table.vue`（横屏表格页）页根写死 `height: 100vh`，小程序 vh 含原生导航栏高度，flex 列内容被顶出可视区——改为 `calc(100vh - var(--window-top, 0px))`。
- **验证**：桌面构建与单测通过；移动端需真机回归（小程序导航栏高度路径）。

### R3 发音延迟、偶发网络错误、专注内不自动连播、小窗第一词只发音一遍

- **现象**：点击发音有延迟；偶发"网络错误"提示；专注模式不自动播放下一个词；小窗口第一个词只播一遍。
- **来源**：sl问题.md「英文发音……只是慢……语音会有延迟……专注里没有自动播放下一个」「小窗口第一词，只发音一遍」。
- **排查结论（2026-11-16 代码走查）**：专注窗连播机制完整（`speakRepeatedly` 连播 1-3 遍 + `scheduleAutoNext` 自动推进 + 暂停/继续 + 6 秒超时兜底）。根因倾向：
  1. **默认值**：`autoNextEnabled` 与 `autoSpeakEnabled` 默认关、`repeatCount` 默认 1——「不自动下一个」「第一词只播一遍」与默认配置一致，属入口不够显眼而非功能损坏；是否改默认待产品决策；
  2. **引擎延迟**：「网络错误」来自在线发音引擎（有道等）偶发失败，TTS 适配器已有代次丢弃防抢播，引擎响应时间代码侧不可控。
- **状态**：列 P2 观察；待 uTools 真机复现后专项（记录 autoNext/repeat 设置值、复现时的引擎与报错文案）。

### R4 专注模式运行期间打开翻译页，专注窗口卡退

- **现象**：专注窗口运行中，主窗口打开翻译页后专注卡退；打开单词列表页无此问题。
- **来源**：sl问题.md「在专注模式运行期间，打开翻译后，专注模式卡退了」。
- **排查结论（2026-11-16 代码走查）**：翻译页（QuickTranslate）打开时仅加载 ≤10 条本地历史 + 可选的路由参数自动翻译（网络请求），无重型初始化、无 OCR/Tesseract 加载；与专注窗的三条通信通道（sendToParent / storage 事件 / DB 轮询）未见高频写入或异常路径。**未发现确定性崩溃路径**。
- **疑似方向**：uTools 多窗口共享插件进程的资源竞争（自动翻译触发密集网络与渲染时专注窗被饿死）、或特定数据/时序条件。
- **状态**：待复现。排查清单：①分离变量——手动打开翻译页 vs 带 `?text=` 参数自动翻译；②复现时录制 Performance；③观察专注窗是冻结还是进程退出；④记录翻译引擎与结果大小。

### R5 删除无二次确认——已被现有代码覆盖

### R7 多诗词导入进度提示——已修复（2026-11-16）

- **根因**：`TextMemory.vue` `handleImportArticles` 逐篇 `await addArticle` 落库，而 `addArticle` 每次全量重写整个 textMemory 文档，N 篇即 N 次全量写，大批量（整本诗词库）耗时明显且全程无反馈。
- **修复**：篇数 > 5 时显示常驻进度提示（「正在导入第 x/N 篇…」，逐篇刷新），每篇之间 `setTimeout 0` 让出主线程保证提示可渲染（uTools 下 db 写入为同步）；结束/异常统一在 `finally` 关闭提示。提示句柄收敛在闭包内管理，规避控制流窄化问题。
- **验证**：`npm run type-check` 通过，`src/views/TextMemory` 36 条测试通过。

# slowlyRecord 问题修复与测试验证计划

## 一、目标与已确认决策

目标是先消除数据损坏和不可用问题，再修正同步语义、复习算法及工程效率，避免把所有改动混成一次不可审查的大重构。

已确认的产品决策：

1. **同步采用兼容优先**：保留现有 AES/XOR 两条链路及旧 XOR 数据读取能力，不引入新的加密依赖，不更换同步协议；但 XOR 兼容通道默认不再携带翻译/OCR 密钥，界面文案必须与实际能力一致。
2. **复习采用“到期即可升级”**：达到当前等级复习间隔后，答对即按牢固度升级，不再设置升级截止窗口；未到期答对仍不升级。
3. **降级规则以桌面当前实现为基准**：普通等级每次 `-4`，下限为 1；12 级答错降到 8 级。
4. **兼容性优先于数据格式折腾**：新增时间戳、稳定 ID 等字段均为可选字段；旧同步包、旧分片、旧词库继续可读，不做全量数据迁移。
5. 每阶段独立修改、独立测试、独立交付；不顺带重构 UI、目录结构或翻译模块。

## 二、实施顺序总览

1. P0：Electron 专注窗口、移动端分片数据安全、IndexedDB 写入真实性。
2. P1：同步写入结果、设置冲突重试、已有数据合并、稳定 ID、删除传播。
3. P2：SRS 算法统一及文档口径。
4. P3：兼容同步的敏感字段与文案、哈希去重、读取性能。
5. P4：移动端类型检查、依赖与包体积、全平台回归验收。

每个阶段先添加能复现问题的失败测试，再实施修复。

## 三、P0：阻止功能不可用和数据损坏

### 3.1 Electron 打包版专注窗口加载失败

**涉及文件**

- `electron/main.cjs`
- 新增一个无 Electron 依赖的路径解析小模块，例如 `electron/child-window-target.mjs`
- `src/views/Word/Word.vue`
- `src/views/TextMemory/TextMemory.vue`
- `src/utils/input-method-helper-window.ts`
- `src/adapters/__tests__/window.test.ts` 或新增同目录针对路径解析的测试

**修改步骤**

1. 将子窗口 URL 解析为 `filePath` 和 `search` 两部分；路径部分不得包含 `?`，查询参数不得拼进物理文件名。
2. 开发环境继续使用 `loadURL()` 加载开发服务器地址；生产环境改为 `loadFile(path.join(__dirname, filePath), { search })`。
3. `createBrowserWindow` IPC 在窗口加载完成后再返回 `winId`；加载失败时删除 Map 中的窗口引用、销毁失败窗口并向上抛出错误，不能仍返回成功 ID。
4. Electron 分支在 IPC 成功返回后直接推送初始化快照，不再依赖固定 500ms 猜测页面已就绪；uTools 分支保持原有时序。
5. 检查三个调用入口的异常路径：创建失败时不得增加专注窗口计数，不得残留半初始化代理、定时器或监听器。
6. `input-method-helper.html` 虽无查询参数，也统一走同一解析和错误处理路径。

**回归测试**

- 纯路径：得到原路径，`search` 为空。
- `focus.html?mode=text`：文件名为 `focus.html`，`search` 保留 `mode=text`。
- 单词专注的长查询串：中文、空格、多个 `&`、重复键和编码后的值不被破坏。
- `input-method-helper.html`：保持现状，不产生多余 `?`。
- 加载失败时 IPC reject，窗口 Map 无残留，父窗口不增加专注计数。

**实际运行验收**

- 开发模式分别打开单词、文本、输入法键盘浮窗。
- `npm run pack:electron:dir` 后，在打包目录版本重复以上操作；确认不再出现 `%3F` 和 `ERR_FILE_NOT_FOUND`。
- 浮窗内复习一次、修改一次设置、关闭再打开，确认数据写入和计数正常。

### 3.2 移动端分片覆盖失败导致旧数据不可读

**涉及文件**

- `mobile/src/adapters/index.ts`
- `mobile/src/adapters/db-miniprogram.test.ts`

**修改步骤**

1. 不再在写入前调用 `cleanupExistingChunks()` 删除当前有效分片。
2. 大文档使用带写入代次的新分片键，例如 `key__chunk__<generation>__<index>`；新分片与旧分片不互相覆盖。
3. 大文档流程调整为：写完全部新分片 → 写入指向新分片的主元数据 → 主元数据成功后再删除旧分片。
4. 任一新分片或主元数据写入失败，只清理本次新分片；主键仍指向旧分片，旧文档必须继续可读。
5. “分片文档改为普通小文档”时，先成功写入普通主文档，再删除旧分片；主文档写入失败时保留旧主元数据和旧分片。
6. 同步 `put`、异步 `asyncPut` 共用相同的提交规则，避免两套实现再次出现不同故障语义。
7. `allDocs()` 继续排除所有内部分片键；保留读取旧格式分片的兼容逻辑。

**回归测试**

- 旧大文档覆盖时，第 2 个新分片写失败：返回失败，`get()` 仍得到旧内容，旧分片未删除，本次临时分片已清理。
- 主元数据写失败：结果同上。
- 大文档改小文档时主键写失败：旧分片文档仍可读。
- 同步 `put` 和异步 `asyncPut` 分别执行以上故障注入。
- 新写入成功：读取到新内容，旧分片被清理，无内部垃圾键。
- 旧版无代次分片仍能读取、覆盖和删除。

### 3.3 IndexedDB 乐观成功与异步失败静默

**涉及文件**

- `src/adapters/impl/db-indexeddb.ts`
- `src/adapters/impl/__tests__/db-indexeddb.test.ts`
- 所有仍直接调用同步 `db.put()` / `db.bulkDocs()` 的 Web/Electron 共用业务模块

**修改步骤**

1. 以全库搜索结果为清单，将 Web/Electron 共用业务的重要写入统一迁移到 `await db.promises.*`，并检查 `DbReturn.ok/error`；uTools 独立 HTML 中的同步 API 不受影响。
2. `promises.put/remove/bulkDocs` 只有在事务真正完成后才更新同步缓存；失败时保留原缓存并向调用方 reject，不返回假成功。
3. 为同一文档的异步写和遗留同步写建立顺序队列，避免较早完成的旧写入覆盖较新的缓存或磁盘内容。
4. 暂时无法迁移的同步调用必须提供统一错误通知和 `whenIdle()` 刷新入口，不得只 `console.error` 后无人感知；在调用方全部迁移后删除这类临时代偿逻辑。
5. 事务失败、配额失败、数据库关闭等场景均按真实失败传播。

**回归测试**

- IndexedDB 注入写失败：`promises.put` reject，缓存仍为旧值，磁盘旧值不变。
- `remove` 失败：文档仍可读取，不提前从缓存消失。
- 连续 put A、put B、remove：最终磁盘和缓存顺序一致。
- bulk 中单项失败：调用方收到失败，不把整批报告为成功。
- 业务层能向 UI 返回失败，而不是只写控制台。

## 四、P1：修正同步写入和合并语义

### 4.1 所有数据库写入结果必须可追踪

**涉及文件**

- `src/utils/sync-manager.ts`
- `src/utils/sync-manager.test.ts`
- `src/components/SyncDialog.vue`

**修改步骤**

1. 增加统一的结果检查辅助逻辑：`bulkDocs` 不仅捕获异常，还逐项检查返回数组中的 `ok/error/id/message`。
2. 快捷键、字母训练记录及其他远端文档写入前统一清理版本字段：远端新增文档去除 `_rev`；覆盖本地文档使用本地最新 `_rev`，禁止直接携带远端 `_rev`。
3. 删除批量写入中的空 `catch { /* skip */ }`；单条失败要记录具体模块和文档 ID。
4. `restoreSyncData()` 改为按模块分别捕获错误：一个模块失败不阻止其他模块恢复，但只要任一模块失败，总结果 `success=false`，并在 `errors` 中给出可定位的信息。
5. `wordBanksRestored` 记录实际成功数；各 `*Restored` 仅在实际成功后设置。检查 `saveWordBank()` 等布尔返回值，不能忽略。

**回归测试**

- mock 适配器严格执行 `_rev` 冲突规则，不再默认接受任意 `_rev`。
- 远端 `_rev` 与本地不同：恢复使用本地 rev 并成功覆盖。
- bulk 返回 `{ok:false}` 但不抛异常：恢复结果失败并包含文档 ID。
- 数字模块失败、句子模块成功：句子仍恢复，总结果为失败且明确是部分完成。
- 跳过策略、墓碑过滤后的词库计数不等于输入数量时，返回实际数量。

### 4.6 让删除真正传播，同时保留冲突保护

- 只发生删除、没有新增时仍写库并提示删除数量。
- 文章、句子、数字条目和词库分别覆盖；默认词库不可被误删。

## 五、P2：统一 SRS 算法

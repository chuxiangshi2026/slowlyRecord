- **验证状态**：源码已修复并重新构建（`D:\slowlyRecord-dist` 已刷新）；浏览器实机回归验证见 `docs/blackbox-e2e-testing.md` 的 E2E 流程。

## 二、待修复 Bug 清单

### B2 文本记忆页整页空白（P0，Web 端，待复现）

- **现象**：整页空白，连页头都没有，仅剩深色背景。
- **复现路径**（单次出现，未稳定复现）：文本记忆页（当时有数据、显示正常）→ 按 Escape 关闭抽屉 → 页面整页空白。
- **证据**：`docs/screenshots/web/04-text-memory.png`（11-10 10:13 版，工作区留存）。
- **疑似方向**：
  1. Escape 键全局监听与 Element Plus drawer 的 Esc 关闭叠加，触发组件卸载异常；
  2. 层叠上下文问题：参照 `AGENTS.md` 中 InkBackground 的约定（页面根节点需 `position: relative; z-index: 0`），文本记忆页路由切换后可能丢失根节点层叠上下文，被背景层盖住；
  3. 渲染崩溃（Vue 渲染错误导致整树卸载）。
- **建议排查**：给 `src/views/TextMemory/TextMemory.vue` 根节点确认层叠上下文；检查 App 级 `onErrorCaptured`/`window.onerror` 是否有上报通道；在 E2E 中加入「抽屉打开 → Escape → 断言页头存在」的回归用例（见黑盒测试文档）。
- **当前状态**：uTools 端实机进入文本记忆页多次均正常，Web 端本轮未再复现。**待复现后修复**。

### B3 页头背景色带与对比度（P2，uTools 端，自定义背景图开启时全页面）

- **现象**：用户设置自定义背景图后，页头一行（页面标题 + ☰ + ⋯ + 🔥）透出背景图的黄绿色带，与下方内容区的深色遮罩观感不协调；页头白色文字在亮色色带上对比度偏弱。
- **证据**：uTools 实机截图（单词页 / 文本记忆页 / 知识库页均可见）。
- **疑似方向**：页头区域未和内容区使用同一遮罩变量，半透明背景直接透出背景图。
- **建议修法**：页头背景使用 `--sr-bg-primary`（或 solid 变量）而非半透明；或给页头单独加一层遮罩渐变。注意遵守 `AGENTS.md`：不硬编码颜色、不引入蓝色系。

### B4 启动器输入功能名被当成单词加入复习列表（P3，uTools 端）

- **现象**：uTools 主输入框输入「文本记忆」后回车，没有进入文本记忆功能页，而是把「文本记忆」四个字作为一张新单词卡加入复习列表（总数 310 → 311）。而输入「翻译」「慢记」则能正确进入对应功能。
- **影响**：用户想用功能时误加脏数据；与「翻译」关键字的行为不一致。
- **疑似方向**：功能关键字匹配结果排在「文本透传（加入复习列表）」之后，Enter 命中了后者；或「文本记忆」功能的 keyword 注册与显示名不一致。
- **建议修法**：提高功能关键字结果的匹配优先级；或对纯功能名命中时给出「进入功能 / 添加为单词」的双结果提示。
- **复测（2026-11-10 17:0x）**：怀疑与当日挂载的 dev 插件项目（已损坏、抢关键字、有划词加单词行为）干扰有关，待移除 dev 插件后复测。
- **结论（2026-11-11，关闭，非 bug）**：dev 插件移除后，用户实机手动复测确认正常——剪贴板有内容时启动器优先展示「加入复习列表」（over 类型透传），在搜索框手动输入功能名则正确进入对应功能，属 uTools 平台标准匹配行为，与「翻译」等功能一致，无需修复。注：自动化注入的打字会落入剪贴板槽位，模拟不出该场景，此类启动器行为以人工实测为准。

### B5 ☰ 菜单抽屉记忆上次滚动位置（P3，全平台，已修复 2026-11-11）

- **现象**：抽屉重新打开时停留在上次的滚动位置，顶部入口（📝 单词 / 📚 知识库 / 📜 文本记忆）不可见，用户需要手动向上滚动才发现主入口。
- **证据**：uTools 实机巡检——首次打开抽屉首屏竟是「数字记忆」，向上滚才能看到「单词」。
- **建议修法**：`MoreDrawer` 打开时（watch visible）将滚动容器 `scrollTop = 0`。
- **复测（2026-11-10）**：Web 端大视口内容不满屏不可复现；uTools 实机多次打开抽屉停留在中部，确认真实存在。
- **修复（2026-11-11）**：`src/components/MoreDrawer.vue` 增加 watch——抽屉每次打开时将 `.el-drawer__body` 的 `scrollTop` 归零（nextTick + 滑入动画后各执行一次）。
- **验证**：vue-tsc 通过；3134 个单元测试全过；黑盒 E2E 43/43 通过（含 F1/F2/B2 守卫）；Puppeteer 实测「打开→滚到底→关闭→重开」重开后 scrollTop=0 回到顶部。已重新构建并更新已安装 uTools 插件 asar（旧包备份 `*.asar.bak-20261111`）。

### B6 「快速开始」对话框底部按钮贴边（P3，uTools 端小窗口，疑似已修复，待实机确认）

- **现象**：数字记忆页「快速开始」向导对话框，底部「下一步」按钮紧贴窗口下边缘（753px 窗口高度下视觉上几乎被裁切）。
- **建议修法**：对话框内容区设置 `max-height: calc(100vh - Npx)` 或让 footer 固定、内容区滚动。
- **复测（2026-11-10，最新 dist）**：753px 视口对话框底距窗口底 149px 正常；560px 矮视口必现贴边。uTools 有效视口约 713px，理论上不触发。
- **结论（2026-11-11）**：早上观察到贴边时安装的还是旧版 asar，最新构建在 uTools 有效视口下应已不复现。**待 uTools 实机最终确认**；若确认复现，修法：对话框内容区 `max-height: calc(100vh - Npx)` 或 footer 固定、内容区滚动。

### B7 全新用户全模块空态无引导（P3，全平台）

- **现象**：未导入数据时，知识库等各模块仅显示「暂无知识库，点击上方导入」类空态文案，无操作引导、无示例数据入口。
- **建议**：空态卡片加「导入示例数据 / 查看使用指南」按钮；或首次启动提供引导流程。

### B8 ☰ 菜单抽屉中下部项目点击穿透——已排除，非产品 Bug（自动化注入输入兼容问题）

- **现象**：☰「更多」抽屉打开后，只有最上面约 1-2 行菜单项（约 y<505 的一窄条区域）可点击；其下所有可见菜单项（记忆宫殿、句子库、字母映射、音标学习、记忆力测试等）点击时**穿透到背后的单词页**——表现为：抽屉被关闭（相当于点到了遮罩）、背后单词卡被选中，但路由不发生跳转。
- **证据**（2026-11-10 下午，KimiCU 注入式输入反复实验，窗口 1004x753，抽屉按使用频率排序后各项目行 y 坐标经截图逐一确认）：
  - 点击 y=487「知识库」行 → 正常跳转 `#/knowledge-memory`（对照组成功）；
  - 点击 y=552 / y=603 / y=617 / y=682 的「记忆宫殿」行（多轮、不同 x 坐标 81/300）→ 全部穿透，未跳转；
  - 点击 y=430「句子库」行（抽屉滚动后的状态）→ 穿透，未跳转；
  - 穿透时背后单词卡出现选中高亮（如 Pretty good / You're welcome / Goodbye），证明点击落到了遮罩层之下的页面元素上；
  - 同一套坐标在 Web 端（Puppeteer 驱动最新 dist）执行抽屉导航 → 全部正常跳转，JS 无报错；uTools 端 JS 直触（非坐标）也可正常导航，排除路由代码问题。
- **疑似方向**：
  1. uTools 插件窗口为透明背景（body 半透明透出桌面壁纸），遮罩/抽屉面板在窗口下部的命中测试区域缺失（uTools 窗口 click-through 区域）；
  2. `el-drawer`（direction=btt, size=62%）面板底部超出实际可命中区域，溢出内容可见但不可交互；
  3. 抽屉内容区高度计算与 uTools webview 视口高度不一致。
- **建议排查**：在 uTools 端用真实鼠标手动验证（点抽屉第 4 项往后）；若属实，检查 MoreDrawer 根节点/遮罩的 `pointer-events` 与面板高度；考虑将抽屉 `size` 改为 `min(62%, 可交互高度)` 或 body 高度改为 `calc(100vh - header)`；同时建议给这些页面补充关键字入口兜底。
- **当前状态**：**已排除（2026-11-10 16:33 用户真机鼠标确认）**——真实鼠标点击抽屉任意项目均可正常进入，仅响应略慢。
- **结论**：这是 KimiCU 注入式输入与 uTools 透明窗口的兼容问题（注入点击未产生真实鼠标的 hover/move 轨迹，落在窗口透明区域时被穿透），**不是产品缺陷**。
- **遗留提示**：1) 后续用注入式输入对 uTools 端做 E2E 时，抽屉中下部项目的坐标点击不可靠，需改用关键字入口或 JS 直触；2) 用户反馈点击响应「有点慢」，可观察 `MoreDrawer` 点击后的路由切换是否有可优化的延迟（低优先级）。
